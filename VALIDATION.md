# Проверка комплекта перед сдачей

28.10.2026. Это проверка документов и диаграмм проекта, а не production-испытание RetailCore.

## Выполнено

- Фактическое задание спринта 4 прочитано на платформе: контекст, все четыре раскрытых раздела и состав сдачи. Требования связаны с артефактами в REQUIREMENTS_MATRIX.md.
- Прочитаны пять предоставленных стенограмм, фрагмент кода и исходный PlantUML. Версия локальных копий зафиксирована SHA256; публичные ссылки сохранены. Полные исходники курса не входят в Git.
- Структура ACC сверена с первоисточником arc42; три шаблона трансформации — с фактическим уроком.
- Содержательно сверены границы AS-IS/TO-BE, отсутствие двойного writer и внешних эффектов пилота, связь roadmap и cutover, сохранение неизвестных количественных требований.
- Обе схемы сгенерированы из общего описания в редактируемый drawio и SVG/PNG. Представления визуально просмотрены; исправлены перекрытия подписей и маршрут линии захвата.
- `tools/validate.py` проверяет обязательные файлы, относительные ссылки, XML drawio/SVG, концы/подписи связей, контрольные суммы семи исходных файлов и 27 строк матрицы покрытия.
- Скрипты — вспомогательные средства подготовки документов; сетевой fetch запускается отдельно по необходимости. Секреты/реальные данные/локальные учётные файлы не добавляются в решение.

## Воспроизведение

Python 3 с Pillow для генерации схем; проверка комплекта использует стандартную библиотеку. На свежем clone для сравнения контрольных сумм сначала выполнить `python tools/fetch_sources.py`, затем `python tools/validate.py`. Повторная генерация изображений: `python tools/build_diagrams.py`; в Windows используется Arial. Наличие изображений в PR позволяет ревью без установки этих средств.

## Границы проверки

Не проводились интервью с реальными сотрудниками, тесты реальной Oracle/CDC, измерение SLA/RPS, deployment, доступ к production и cutover. Q-01–Q-12, baseline/целевые значения, capacity, восстановление, безопасность копии и stakeholder sign-off — условия будущего внедрения. Сдача проектного решения не равна разрешению на production-переключение.

GitHub-публичность, состав опубликованного PR и фактическая отправка платформе проверяются после локального аудита. Итог отправки фиксируется в локальном журнале курса; после неё ветка решения не изменяется до ревью.
